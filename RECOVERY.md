# Recovery — rebuilding the pipeline from scratch

This document is what you (or someone else) reads on a fresh machine when the original drive is gone. The repo has all the irreplaceable assets — code, configs, training corpus. Everything else is regenerable.

## What's actually in this repo

| asset | location | size | rebuildable? |
|---|---|---|---|
| **Pipeline source** | `python/`, `scanner.py`, `*.ps1` | ~few hundred KB | no — this is the IP |
| **Custom binaries** | `jkdemometadata.exe`, `python/trimming/DemoTrimmer.exe` | ~600 KB | only if source is checked in alongside |
| **Training corpus** | `python/predict/{good,bad,ok,ignore}_*_aggregated.json` | ~few MB | no — this is months of hand-labelling |
| **Trimmed-name → source map** | `python/trimming/demos output/trimmed_map.json` | ~500 KB | partially (re-running build_jamme_demolist would re-derive entries for clips you re-trim) |
| **jaMME configs** | `a full jka install/.../mme/*.cfg` | ~5 KB | no — these took real debugging to dial in |
| **Documentation** | `README.md`, `archive/**/README.md`, `python/review/README.md` | ~50 KB | no |

What's **NOT** in the repo (intentionally — see `.gitignore`):

- The 1500+ source `.dm_26` demos that produced the corpus. Recoverable from the JACTF demo archive (a community resource, not yours). On a fresh machine, you'd re-fetch via `fetch_jactf_demos.py`.
- The `a full jka install/` JKA assets. Buy on Steam, ~$10.
- All the `*.dm_meta` parsed caches. Regenerated by running `jkdemometadata.exe` on the source `.dm_26`.
- All per-set `*_frags.json` files. Regenerated by running `scanner.py`.
- Renders (`mme/captures/*.mp4`). Regenerated by running stage 5.
- venvs. Recreated by `pip install -r requirements.txt`.

## Step-by-step recovery on a fresh Windows machine

Time required: ~2 hours, mostly waiting for downloads.

### 1. Install prerequisites

- **Python 3.13** from python.org (3.11+ works, 3.13 is canonical here)
- **ffmpeg** for Windows from [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) — pick a "full" build, drop the bin folder onto PATH, verify with `ffmpeg -version`
- **Jedi Academy** — buy/install via Steam. Take note of the install path.
- **jaMME** — download from its GitHub releases, extract on top of the JKA `GameData/` directory. You should now have `jamme.exe` in `GameData/`.
- **Git** — for cloning this repo.

### 2. Clone this repo

```powershell
cd D:\
git clone <your-private-repo-url> JACTF
# or wherever you want it. Path doesn't matter — auto-detection handles it.
cd JACTF
```

### 3. Set the GameData path

The pipeline auto-detects everything inside the repo, but `GameData` lives outside. Set the env var:

```powershell
# one-time, persistent for your user
[System.Environment]::SetEnvironmentVariable(
    'JACTF_GAMEDATA',
    'C:\Program Files (x86)\Steam\steamapps\common\Jedi Academy\GameData',
    'User'
)
# Or copy .env.example to .env and edit. (We don't currently have a .env loader,
# but env vars set via PowerShell or System Properties → Env Vars work.)
```

You'll need to restart your shell after setting a User env var.

### 4. Install the mme configs into your GameData

Copy the configs from this repo into your JKA install:

```powershell
$repo = $PSScriptRoot   # or wherever you cloned to
$gd   = $env:JACTF_GAMEDATA

Copy-Item "$repo\a full jka install\game_directory\Jedi Academy\GameData\mme\*.cfg" `
          "$gd\mme\" -Force
Copy-Item "$repo\a full jka install\game_directory\Jedi Academy\GameData\render_resilient.bat" `
          "$gd\" -Force
```

These are the configs that took real debugging to dial in (`mme_pipeCommand`, `capture pipe 60 clip` autoexec, `cg_drawTimer 1`). Without them rendering won't work even if jaMME is installed.

### 5. Create venvs and install Python deps

```powershell
# Top-level venv (used by run_pipeline.ps1)
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r python\fetch\requirements.txt
pip install -r python\predict\requirements.txt
deactivate

# Review UI venv — created on first run.bat
# (skip; happens automatically the first time you launch the review UI)
```

### 6. Re-fetch demos (optional — only if you want to re-derive aggregated training data)

```powershell
.\venv\Scripts\Activate.ps1
python python\fetch\fetch_jactf_demos.py --since 30d
```

This pulls the last 30 days of new matches. Backfill further with explicit windows (`-Since 60d -Until 30d`, etc.).

You don't actually **need** to do this on a recovery — the aggregated training corpus already lives in `python/predict/*_aggregated.json` and is what predict reads. Re-fetching only matters if you want to make new predictions, which is the next step.

### 7. Run the pipeline end-to-end

```powershell
.\run_pipeline.ps1 -Since 1d -LimitClips 5
```

That fetches → parses → predicts → trims → renders 5 candidate clips. Smoke test.

### 8. Review and verify

```powershell
cd python\review
.\run.bat
# open http://127.0.0.1:5057/
```

If you see the 5 rendered clips and can vote on them, recovery is complete.

## Things that fail predictably on a fresh machine

- **`ffmpeg` not on PATH** — see the gotcha in the main `README.md`. jaMME silently writes 0-byte frames. Verify with `ffmpeg -version` from `GameData/` cwd.
- **`JACTF_GAMEDATA` not set** — the pipeline assumes the in-repo default which won't exist on your fresh install. Set the env var before running anything.
- **mme configs not copied** — render_clips.py succeeds in launching jaMME but no capture happens. The give-away is "BATCH starting capture pipe to ffmpeg" missing from `mme/qconsole.log`.
- **JKA assets missing** — jaMME crashes immediately on startup with a missing-base error. Solution: actually install JKA before installing jaMME on top.

## What's NOT recoverable (genuinely lost)

If the original drive dies and only this repo survives, you lose:

- **The 1,516 hand-labelled demos in `archive/training_demos/demo_files/{good,bad,ok}/`.** The features they produced (rows in the aggregated corpus) survive in the repo. But if `jkdemometadata.exe` ever changes its output schema enough that you need to re-extract from raw demos, those raw demos are gone.
- **Renders (`mme/captures/*.mp4`)** — but these are cheap to regenerate; just re-run stage 5.
- **JACTF download history (`python/fetch/seen_matches.json`)** — regenerable by re-fetching, just slower (the API will return the demos but the dedup state is gone).
- **Render history (`mme/render_state.json`)** — regenerable trivially, just means the next batch re-renders everything.
- **Review session logs (`python/review/sessions/`)** — these are audit artifacts; their absence is fine for the pipeline but you've lost the per-session history.

If any of those losses matter, set up a separate backup of `archive/training_demos/` to cloud storage (Backblaze B2, Cloudflare R2, etc.) — the source repo isn't the right place for ~30 GB of demos.

## Sanity check after recovery

```powershell
# pipeline scripts compile
python -m py_compile scanner.py
python -m py_compile python\fetch\fetch_jactf_demos.py
python -m py_compile python\predict\*.py
python -m py_compile python\review\*.py

# auto-detection resolves correctly
python -c "from pathlib import Path; import os; print(Path(os.environ.get('JACTF_ROOT') or Path('.').resolve()))"

# corpus is intact
python -c "import json; print('good:', len(json.load(open(r'python\predict\good_client_frags_aggregated.json'))))"
python -c "import json; print('bad:',  len(json.load(open(r'python\predict\bad_client_frags_aggregated.json'))))"
python -c "import json; print('ok:',   len(json.load(open(r'python\predict\ok_client_frags_aggregated.json'))))"
python -c "import json; print('ignore:', len(json.load(open(r'python\predict\ignore_frags_aggregated.json'))))"

# trimmed_map is intact
python -c "import json; print('mappings:', len(json.load(open(r'python\trimming\demos output\trimmed_map.json'))))"
```

If those all return reasonable numbers (currently good: ~570, bad: ~1270, ok: ~350, ignore: ~380), you're back in business.
